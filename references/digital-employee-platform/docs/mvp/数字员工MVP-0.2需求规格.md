# 数字员工 MVP 0.2 需求规格

> 版本：MVP-0.2  
> 日期：2026-08-26  
> 状态：原型已实现，待用户手动验收  
> 基线：继承 [`数字员工MVP需求与事件合同.md`](./数字员工MVP需求与事件合同.md)；未在本文变更的 0.1 能力继续有效。

## 1. 目标

在已跑通的“员工广场 -> 员工工作台 -> 实时执行”链路上增加四项最小产品能力：

1. 用服务器 JSON 管理数字员工；
2. 在执行前完成关键词和安全审查 Agent 检查；
3. 对附件强制标注公开、受控或内部；
4. 使用受控 A2UI 完成安全二次确认、执行中关键操作审批和输出文件分级。

本阶段仍是可落地原型，不扩展成完整管理平台。

### 1.1 原型安全边界

本阶段的安全能力用于验证用户体验：用户能看到任务正在审查、风险提示、人工确认和文件密级标注。它不承诺抵抗浏览器开发者工具、直接调用接口或专业攻击，也不建设生产级 DLP、审批账本、鉴权和防绕过机制。

智能审查不得长期阻塞任务入口。关键词规则同步完成；本地模型审查默认最多等待 5 秒，模型不可用、超时或输出无法解析时，明确回退到 A2UI 人工确认，由用户决定是否继续。

## 2. 用户流程

### 2.1 员工管理

```text
管理员进入 /admin
  -> 查看员工列表
  -> 新增或编辑员工
  -> 保存到服务器 JSON
  -> 员工广场读取最新公开资料
```

管理页支持新增、编辑、启用和停用员工。本地原型不增加登录、管理密码、用户系统或 RBAC。

### 2.2 安全审查与执行

```text
用户选择员工
  -> 输入任务并选择附件分级
  -> 关键词检查
  -> 安全审查 Agent 返回 allow / deny / confirm
      -> allow：进入 Evo-Harness
      -> deny：显示拒绝原因并结束
      -> confirm：通过 A2UI 请求用户二次确认
          -> 确认继续：进入 Evo-Harness
          -> 取消任务：结束
  -> AG-UI 实时传输执行事件
  -> Markdown、工具、文件和终态组件分别展示
```

### 2.3 执行中审批

现有 Evo-Harness Web 通道没有工具执行前暂停事件，因此本原型不伪造执行中拦截。安全审查识别到发送、外部写入、脚本或批量修改等关键操作时，在执行开始前统一进入 A2UI 二次确认。未来底层提供可暂停事件后，再把同一 A2UI 确认组件接到执行中节点。

### 2.4 输出文件分级

```text
Evo-Harness 产生文件
  -> AG-UI 接收文件事件，界面暂不展示下载入口
  -> A2UI 展示文件信息和密级下拉框
  -> 用户选择公开 / 受控 / 内部
  -> 前端记录密级并开放预览或下载入口
```

每个输出文件都必须由用户明确选择密级。未完成分级时，产品界面保持“等待分级”，不显示预览和下载入口；文件 URL 可能已经存在于浏览器状态中，本原型不宣称具备防绕过能力。

## 3. 员工 JSON 合同

员工配置保存在服务器侧 `mvp/data/employees.json`，由 Next.js Route Handler 读取和更新。浏览器不得直接导入或访问该文件。

每条员工记录至少包含：

```json
{
  "id": "researcher",
  "name": "研究员",
  "role": "行业研究",
  "description": "负责资料检索、比较和结论整理",
  "systemPrompt": "仅服务端可见的员工 Prompt",
  "tags": ["检索", "分析"],
  "quickQuestions": ["梳理这个主题的关键事实"],
  "avatar": "/avatars/researcher.png",
  "status": "enabled",
  "sortOrder": 10
}
```

### 3.1 普通页面展示字段

员工广场和工作台只展示：

- `id`
- `name`
- `role`
- `description`
- `tags`
- `quickQuestions`
- `avatar`
- `status`
- `sortOrder`

### 3.2 Prompt 展示边界

`systemPrompt` 由管理页编辑，普通员工广场和工作台不展示。为了保持原型简单，员工接口和浏览器数据可以包含该字段；本阶段只验证产品界面不主动暴露，不把它表述为真正的保密控制。

浏览器提交任务时只发送 `employeeId`，服务端根据 ID 加载员工 Prompt 并组装 Evo-Harness 请求。JSON 保存前必须经过 Zod 校验，并采用临时文件加原子替换，避免中途写坏配置。

## 4. 用户可见命名边界

用户可见产品统一称为 **Evo-Harness**。页面文案、状态提示和普通错误信息不显示底层执行器原名。

- 页面和提示文案；
- 下载文件名和运行状态。

内部请求路径、代码名称和调试事件可以继续沿用现有适配器，用户不在正常产品流程中感知即可。

## 5. 安全审查合同

### 5.1 两层检查

1. **关键词检查**：服务端规则快速识别明确禁止内容；
2. **安全审查 Agent**：使用独立、固定的系统 Prompt 审查任务、附件元数据和必要的附件文本摘要。

安全审查 Agent 只能返回以下结构化结果：

```json
{
  "decision": "allow | deny | confirm",
  "riskLevel": "low | medium | high",
  "categories": ["风险分类"],
  "summary": "可展示给用户的脱敏说明"
}
```

- `allow`：继续执行；
- `deny`：不调用 Evo-Harness，显示脱敏原因；
- `confirm`：进入 A2UI 二次确认。

用户确认后再次提交同一任务并跳过本轮审查。本原型不实现一次性审批令牌、有效期或防重放账本。

### 5.2 Prompt 注入和思维链保护

- 审查 Prompt 明确把用户文本和附件描述标记为不可信数据；
- 普通页面不展示员工 Prompt 和安全审查 Prompt；
- UI 不展示原始思维链，`<think>` 等标签按普通文本处理；
- UI 只展示阶段提示和工具事实；
- 安全审查 Agent 的输出必须通过 Zod Schema，解析失败时按拒绝处理；
- 安全审查通过不等于获得工具权限，关键操作仍需执行中审批。

## 6. 附件分级合同

用户添加每个附件时必须选择一个等级：

| 等级 | 含义 | MVP 处理规则 |
| --- | --- | --- |
| 公开 | 可以公开流转的内容 | 正常进入审查和执行 |
| 受控 | 仅限授权场景使用 | 进入审查；发送或外部写入前必须审批 |
| 内部 | 仅允许本地处理 | 禁止通过网络、发送类工具对外传输 |

未选择等级时，前端禁止提交，服务端也必须拒绝。普通界面只展示附件名称和密级，不主动展示 Evo-Harness 返回的本地路径；路径或文件地址可能存在于接口响应和浏览器状态中，本原型不把它作为保密边界。

附件元数据至少包含：

```json
{
  "attachmentId": "att_123",
  "name": "report.pdf",
  "mimeType": "application/pdf",
  "size": 1024,
  "classification": "public | controlled | internal"
}
```

### 6.1 输出文件分级

Evo-Harness 产生的文件、报告和其他 Artifact 同样必须标注 `public | controlled | internal`，但密级由用户在文件交付前通过 A2UI 表单选择。

- 前端为文件分配稳定 `artifactId`；
- 分级前只展示文件名、类型、大小和提示，不显示预览或下载入口；
- 每个文件单独分级，不使用静默默认值；
- 分级完成后，前端才显示正式文件卡和下载入口；
- 多个文件可以依次处理，但任何未分级文件都不能因为同批其他文件已分级而被自动发布。

输出文件元数据至少包含：

```json
{
  "artifactId": "artifact_123",
  "runId": "run_123",
  "name": "result.pdf",
  "mimeType": "application/pdf",
  "size": 2048,
  "classification": "public | controlled | internal | pending"
}
```

## 7. AG-UI 与 A2UI 合同

AG-UI 负责文本、阶段、工具、附件、审批请求和用户决定的传输；A2UI 只负责渲染受控界面。

MVP 0.2 支持四类受控 Surface：

1. `security_confirmation`：安全审查后的二次确认；
2. `operation_approval`：保留的执行中关键操作审批类型，当前底层尚不触发；
3. `information_form`：执行继续前必须补充的字段；
4. `artifact_classification`：输出文件交付前选择公开、受控或内部。

允许的 action 仅包括：

- `confirm_and_continue`
- `cancel_run`
- `approve_operation`
- `reject_operation`
- `submit_information`
- `classify_artifact`

A2UI 仍使用组件白名单和 Zod Schema，不接受任意 JSX、JavaScript、CSS、URL 或底层组件 Props。

## 8. 实时展示

员工工作台继续实时展示：

- Markdown 回答；
- 执行阶段；
- 工具开始、进度、结果和权限拒绝；
- 记忆检索和子 Agent 步骤；
- 图片、文件和产物；
- 输出文件等待分级、已分级和可下载状态；
- 审查中、等待确认、执行中、等待审批、完成、失败和取消状态。

产品层使用中性事件名称，未知事件保留诊断信息但不得暴露内部名称、路径、凭据或隐藏 Prompt。

## 9. 头像规范

- 前端统一使用项目内 Avatar 组件，不在页面中分别处理图片尺寸和裁剪；
- 管理页支持选择或上传本地头像，并立即预览；
- 头像使用固定比例、尺寸、圆角和背景规则；
- 图片缺失时使用姓名首字或 Lucide 岗位图标兜底；
- 运行时不依赖公网头像服务；
- 本阶段选择一套风格一致的本地头像资产，不混用照片、3D 人像、插画和图标。

## 10. 明确不做

- 数据库、聊天记录持久化和历史运行台账；
- 登录、多租户、用户体系和完整 RBAC；
- dsh、LoopX 和长任务；
- assistant-ui、CopilotKit 或第二套聊天/runtime；
- 通用内容安全平台、规则编辑器或复杂审批中心；
- 让模型生成任意前端代码或样式。
