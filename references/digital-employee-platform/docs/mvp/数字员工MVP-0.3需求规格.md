# 数字员工 MVP 0.3 需求规格

> 版本：MVP-0.3  
> 日期：2026-08-27  
> 状态：原型已实现，待用户手动视觉验收  
> 基线：继承 [`数字员工MVP-0.2需求规格.md`](./数字员工MVP-0.2需求规格.md)；本文只描述 0.3 增量和被替换的旧设计。

## 1. 版本目标

MVP 0.3 面向客户现场演示，目标不是建设完整平台，而是形成一条更完整、更有表现力的数字员工体验：

1. 用户在首页用一句话描述需求，由隐藏的经理员工推荐合适的数字员工；
2. 业务任务执行前，由隐藏的安全审查员工通过 Evo-Harness 完成审查；
3. 员工工作台同时展示员工的配置能力和本轮真实执行事件；
4. `/admin` 增加原型级登录，并能配置员工展示与执行所需字段；
5. 首页和对话页减少空旷感，形成适合客户演示的视觉层级和动态反馈。

本版本优先保证演示完整度、交互反馈和页面表现，不增加生产级权限、安全和审计体系。

## 2. 明确替换的 0.2 设计

以下 0.2 设计在 0.3 中被替换：

- 删除 Next.js 中的正则关键词审查；
- 删除 Next.js 直接调用 `/v1/chat/completions` 的智能审查；
- 所有安全判断规则统一写入安全审查员工的 `systemPrompt`；
- 员工卡片删除“资料数量”和“技能数量”；
- 员工删除拟人化真实姓名，统一以岗位名称作为主标题；
- 员工广场删除“当前可用”筛选，改为业务大类筛选；
- 首页删除“管理员工”入口；
- 原有单纯员工列表首页升级为“一句话指派 + 员工广场”；
- 原有单列对话工作台升级为“快捷问题 + 对话 + 执行舱”。

0.2 已实现的附件密级、输出文件分级、Markdown、AG-UI 事件、A2UI 确认和 Evo-Harness 执行链路继续保留。

## 3. 员工状态语义

本原型继续只使用现有状态：

- `enabled`：在员工广场展示，也可以执行；
- `disabled`：不在员工广场展示，但后端仍可通过员工 ID 读取并执行。

`disabled` 在本阶段只承担“前台不可见”的作用，不建设内部员工类型、专用权限或额外调用限制。管理页展示所有员工，并允许编辑停用员工。

新增两个停用员工：

| 固定 ID | 岗位名称 | 职责 | 状态 |
| --- | --- | --- | --- |
| `manager` | 任务经理 | 理解首页需求并推荐员工 | `disabled` |
| `security-reviewer` | 安全审查员 | 审查业务任务并返回三态结论 | `disabled` |

两个员工都使用与普通员工相同的数据结构、Prompt 组装方式和 Evo-Harness 执行通道。

## 4. 首页：一句话指派

### 4.1 页面结构

首页首屏采用紧凑的任务调度台布局，员工广场必须在首屏下缘可见，不使用占满一屏的大型空白 Hero。

```text
顶部栏：产品标识 + Evo-Harness 本地运行状态
需求接待台：一句话输入 + 指派按钮 + 推荐状态
推荐结果：首选员工 + 简短理由 + 候选员工
员工广场：员工卡片列表
```

顶部栏不得展示 `/admin` 入口。管理员直接访问 `/admin`。

员工广场使用业务大类筛选，不再使用“所有员工 / 当前可用”这种状态筛选。广场本身只返回 `enabled` 员工，因此“当前可用”没有额外信息价值。一级筛选固定显示：

- 全部；
- 办公协作；
- 产品设计；
- 技术工程；
- 数据智能。

`category` 表示员工所属的一个业务大类，用于广场筛选；`tags` 表示该员工自己的具体能力，例如“竞品拆解”“接口联调”“会议纪要”。大类和标签不能混用。当前没有员工的大类不显示，避免出现空筛选结果。

### 4.2 需求接待流程

```text
用户输入一句需求
  -> 点击“帮我指派”
  -> 后端读取停用的 manager 员工
  -> 通过 Evo-Harness 发起独立推荐 run
  -> 页面依次展示“理解任务 / 匹配能力 / 形成推荐”
  -> 解析结构化推荐结果
  -> 高亮首选员工，并弱高亮其他候选
  -> 显示一句推荐理由
  -> 用户点击员工进入工作台
  -> 原始需求自动带入工作台输入框，但不自动执行
```

用户也可以跳过经理推荐，直接点击任意员工卡片。推荐失败、超时或返回内容无法解析时，页面明确提示“暂时无法自动推荐”，保留手动选择员工的完整能力，不阻塞首页。

### 4.3 经理输出合同

经理员工的最终回答必须包含可解析 JSON：

```json
{
  "primaryEmployeeId": "researcher",
  "candidateEmployeeIds": ["researcher", "writer"],
  "reason": "任务需要先整理资料并形成有依据的结论。"
}
```

约束：

- `primaryEmployeeId` 必须是当前 `enabled` 员工；
- 候选员工最多 3 个，必须去重；
- `reason` 是面向用户的一句话，不展示推理过程；
- 结果必须经过 Zod 校验；
- 经理 run 使用独立 `sessionId`，不与业务员工对话共享上下文；
- 推荐等待必须有超时，超时后恢复手动选择，不无限显示加载状态。

### 4.4 员工卡片

员工卡片展示：

- 头像和岗位名称；
- 所属业务大类；
- 一句话职责描述；
- 2 至 3 个能力标签；
- `员工成熟度`；
- `版本号`；
- 推荐状态和推荐理由。

删除 `knowledge`、`skills` 及“38 资料 / 12 技能”等精确数字。替换为模糊、可配置的描述字段：

- `maturity`：例如“成长中”“稳定”“成熟”；
- `version`：例如 `V1.0`、`V1.1`，用于表达员工配置或能力版本，不使用虚构的精确业务统计。

推荐卡片使用边框、局部底色、轻量进入动效和“首选”标识形成明显焦点；不使用大面积渐变、装饰光球或虚构评分。

数字员工不配置或展示拟人化真实姓名。“研究分析师”“流程执行员”“内容编辑”“工程搭档”等岗位名称直接作为卡片和工作台的主标题，不再附加“林舟”“陆衡”等姓名。头像仍可保留，但定位为岗位形象，不暗示真实人员身份。

## 5. 安全审查员工

### 5.1 执行流程

```text
用户在业务员工工作台提交任务
  -> 后端读取停用的 security-reviewer 员工
  -> 将用户任务、附件名称和附件密级组装进审查 Prompt
  -> 通过 Evo-Harness 发起独立审查 run
  -> AG-UI 展示审查开始、进行中、完成或失败
  -> 解析最终结构化结果
      -> allow：启动用户选择的业务员工
      -> confirm：展示 A2UI 二次确认
      -> deny：终止并显示简短原因
```

删除本地关键词快速检查。提示词窃取、角色劫持、`<think>` 标签诱导、敏感数据、外发、脚本执行、危险 SQL、命令注入和破坏性操作等规则全部写入安全审查员工的 `systemPrompt`。

### 5.2 审查输出合同

```json
{
  "decision": "allow",
  "riskLevel": "low",
  "categories": [],
  "summary": "未发现需要阻止或确认的明显风险。"
}
```

约束：

- `decision` 仅允许 `allow | confirm | deny`；
- `riskLevel` 仅允许 `low | medium | high`；
- `categories` 最多 8 项；
- `summary` 只提供可展示的简短理由；
- 结果通过 Zod 校验；
- 审查 run 使用独立 `sessionId`，不污染业务对话；
- 超时、执行失败或结果无法解析时进入 `confirm`，由用户人工决定是否继续；
- 用户确认后直接进入业务员工，不重复执行同一轮审查。

### 5.3 原型安全边界

模型审查用于演示“安全员工参与任务”的产品体验，不承诺发现所有提示词注入、编码绕过或攻击变体。

- 当前系统不执行 SQL 查询，因此没有真实数据库 SQL 注入面；
- 未来接入数据库时必须使用参数化查询，不能依赖审查模型代替工程防护；
- `<think>`、`</think>` 和类似标签按普通用户文本处理；
- 页面不展示原始 reasoning 或隐藏 Prompt；
- Markdown 不执行原始 HTML、JavaScript 或任意前端代码；
- 用户可以观察审查员工的状态、耗时、风险类别、结论和公开理由，但不能查看模型思维链；
- 本版本不建设鉴权、防绕过、审批账本、生产级 DLP 或安全策略管理中心。

## 6. 员工工作台

### 6.1 桌面布局

```text
┌──────────────┬────────────────────────────┬────────────────────┐
│ 快捷问题     │ 对话主区                   │ 执行舱             │
│              │ 消息 / Markdown / A2UI     │ 配置能力           │
│              │ 附件 / 文件 / 输入框       │ 本轮真实执行时间线 │
└──────────────┴────────────────────────────┴────────────────────┘
```

- 左侧保持窄栏，只放快捷问题；
- 中间是唯一主内容区，承担对话、审批和文件交付；
- 右侧执行舱常驻展示能力与事件；
- 顶部仅保留返回、员工身份和 Evo-Harness 状态；
- 页面不堆叠欢迎卡、统计卡或无意义说明。

窄屏下中间对话优先，快捷问题和执行舱通过抽屉或顶部切换入口打开，不能把三栏压缩到同一屏幕。

### 6.2 左侧快捷问题

- 展示管理员为当前员工配置的 `quickQuestions`；
- 点击后填入对话输入框，不自动发送；
- 最多展示 6 条；
- 无快捷问题时不显示空面板。

### 6.3 右侧执行舱

执行舱在一个连续空间中展示两类信息：

1. **能力配置**：员工被配置为具备的原子能力、Skill 和知识方向；
2. **本轮执行**：Evo-Harness 真实返回的阶段、工具调用、子 Agent、文件和终态。

两类信息不强制拆成两个页签，但必须使用明确标题和不同视觉状态。静态能力表示“员工会什么”，真实事件表示“本轮做了什么”。

执行舱需要支持：

- 任务未开始：显示配置能力和“等待任务”；
- 审查阶段：显示安全审查员工状态、耗时和结果；
- 执行阶段：按时间顺序追加真实事件；
- 成功：显示完成状态和实际产物；
- 失败、取消、断线重连：显示对应状态和可理解的错误；
- 未知事件：使用通用事件项展示，不让页面报错。

### 6.4 真实事件与配置能力

当前 Evo-Harness Web 通道可以真实提供：

- `phase`；
- `tool_start`、`tool_progress`、`tool_end`；
- `subagent_step`；
- `file`、`image`、`artifact`、`voice_attach`；
- `done`、`cancelled`、`error` 和流终态。

`bash`、`read`、`send`、`memory_search`、`vision` 等通过通用工具事件的工具名识别，前端为已知工具映射 Lucide 图标、中文名称和状态；未知工具使用通用工具图标。

当前没有可靠的独立 `skill_start / skill_end` 事件。因此：

- Skill 作为管理员配置的能力展示；
- 不把静态 Skill 标记为本轮已调用；
- 不从回答文本猜测 Skill 是否执行；
- 后续 Evo-Harness 提供明确 Skill 事件后再接入真实时间线。

## 7. 员工配置合同

员工 JSON 在现有字段上调整为：

```json
{
  "id": "researcher",
  "title": "研究分析师",
  "category": "数据智能",
  "avatar": "/avatars/researcher.png",
  "accent": "#1d6b5b",
  "accentSoft": "#dcefe7",
  "status": "enabled",
  "description": "把分散资料整理成有依据的判断。",
  "tags": ["资料检索", "竞品拆解"],
  "maturity": "成熟",
  "version": "V1.0",
  "capabilities": [
    {"id": "web-search", "name": "资料检索", "kind": "tool", "icon": "Search"},
    {"id": "report", "name": "报告生成", "kind": "skill", "icon": "FileText"}
  ],
  "quickQuestions": ["比较这两个方案的主要差异"],
  "systemPrompt": "员工的隐藏 Prompt",
  "sortOrder": 10
}
```

变更说明：

- 删除 `name`、`role` 和 `initials`；
- 新增 `title: string`，作为前后台统一使用的岗位名称和主标题；
- 新增 `category: string`，每个员工只属于一个业务大类；
- 删除 `skills: number` 和 `knowledge: number`；
- 新增 `maturity: string`；
- 新增 `version: string`，格式为 `V1.0` 或 `V1.0.0`；
- 新增 `capabilities`；
- `capabilities.kind` 仅允许 `tool | skill | knowledge`；
- `icon` 仅允许后台预置的 Lucide 图标名称，不能提交任意 SVG、HTML 或 URL；
- `systemPrompt` 继续由管理页编辑，普通产品页面不主动展示。

## 8. 管理页与原型登录

### 8.1 登录

- `/admin` 未登录时显示独立登录页；
- 固定账号：`admin`；
- 固定密码：`admin`；
- Next.js Route Handler 校验账号密码并设置简单会话 Cookie；
- 登录后刷新页面保持登录；
- 提供退出登录；
- 这是演示登录，不承诺真实安全性。

本版本不增加数据库、用户表、密码散列、找回密码、RBAC 或多管理员。

### 8.2 员工管理字段

管理页支持编辑：

- 岗位名称、业务大类、头像和描述；
- 启用或停用；
- 标签、成熟度和版本号；
- 快捷问题；
- 原子能力、Skill 和知识方向；
- `systemPrompt`；
- 排序和员工配色。

管理页必须能查看和编辑 `manager` 与 `security-reviewer` 两个停用员工。

## 9. 演示表现要求

“酷”来自真实状态和清晰动效，不来自虚构执行数据。

- 经理推荐、审查和业务执行均展示明确阶段变化；
- 员工推荐使用有方向感的聚焦动效，不做循环装饰动画；
- 工具时间线在事件到达时渐进展开，完成后稳定不抖动；
- 已知工具使用一致图标、参数摘要、状态色和结果摘要；
- 员工卡片、工作台和执行舱共用统一色彩 Token；
- loading、empty、error、success、disabled、reconnecting 和 cancelled 状态必须完整；
- 键盘焦点、触控尺寸、响应式和减弱动效偏好继续有效；
- 不编造调用次数、知识库数量、成功率、效率提升或虚假的实时事件。

## 10. 明确不做

- 本地正则关键词安全规则；
- 生产级提示词注入防御、SQL 防火墙或内容安全平台；
- 数据库、聊天记录持久化和历史运行台账；
- 多租户、完整 RBAC 和正式身份系统；
- dsh、LoopX 和长任务；
- 执行前不存在的真实 Skill 调用事件；
- assistant-ui、CopilotKit 或第二套聊天/runtime；
- 前台管理入口和复杂后台导航；
- 模型生成任意 JSX、JavaScript、CSS 或组件配置。
