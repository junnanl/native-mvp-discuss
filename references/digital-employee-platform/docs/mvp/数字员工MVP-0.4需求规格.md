# 数字员工 MVP 0.4 需求规格

> 版本：MVP-0.4  
> 日期：2026-08-27  
> 状态：原型已实现，待用户手动视觉验收  
> 基线：继承 [`数字员工MVP-0.3需求规格.md`](./数字员工MVP-0.3需求规格.md)；本文只描述 0.4 的演示体验增量，不覆盖 0.3 已实现的运行链路。

## 1. 版本目标

MVP 0.4 不改变任务经理、安全审查员和业务员工的后端执行方式，集中改善客户演示时的动态感、信息密度和执行过程可读性：

1. 优化“一句话指派”的等待动画和默认问题；
2. 恢复业务员工对话中的详细执行记录；
3. 限制右侧执行区域的长度，避免事件无限撑高页面；
4. 将底层工具名映射成客户能够理解的产品名称；
5. 提升实时执行区域的色彩、层级和状态反馈。

本版本不增加新的 runtime、数据库、任务历史或生产级安全能力。

## 2. 明确不变的边界

- 任务经理继续通过现有 `/api/dispatch` 完成一次真实 Evo-Harness run；
- 后端继续等待任务经理返回完整结构化结果，再一次性返回推荐；
- 不新增任务经理 SSE、AG-UI 流或第二套推荐协议；
- 不展示任务经理 reasoning；
- 前端可以将等待动画、轮换文案和进度效果呈现为任务经理正在推进的处理阶段；
- 推荐结果仍必须经过现有 Zod Schema 校验；
- 推荐失败或超时后继续允许用户手动选择员工。

## 3. 一句话指派等待体验

### 3.1 状态流程

```text
idle
  -> dispatching
      -> success
      -> error
```

`dispatching` 阶段显示连续的加载动画和阶段状态，让用户明确感知任务经理正在推进工作，但不改变现有后端返回方式。

### 3.2 动态反馈

等待区域至少包含：

- 明显可见且持续旋转的 Loader；
- “任务经理正在处理”的主状态；
- “理解需求 / 匹配员工 / 准备推荐”等阶段纵向排列并按节奏推进；
- 当前阶段高亮，已完成阶段显示完成标识，下一阶段保持等待状态；
- 阶段之间使用进度轨、状态点或轻量切换动效形成连续感；
- 输入框和指派按钮进入禁用状态；
- 推荐成功后通过一次聚焦动效高亮首选员工；
- 推荐失败后停止动画并显示明确错误。

这组阶段作为首页任务经理的演示型执行过程直接展示，不需要向用户解释其内部实现方式。推荐完成后阶段全部进入完成状态，再出现最终推荐结果。

### 3.3 状态互斥布局

输入框始终保留；输入框下方设置固定高度的状态槽，以下四种内容互斥显示：

- `idle`：两条纵向默认问题和“帮我指派”按钮；
- `dispatching`：纵向任务经理阶段链，不显示默认问题和提交按钮；
- `success`：首选员工、推荐理由、耗时、“查看推荐员工”和“重新指派”；
- `error`：错误说明和“重新指派”。

空闲状态不展示阶段链，也不展示“选择示例或输入任务”等额外说明。状态切换只能替换固定槽内的内容，不能向卡片下方继续追加。

### 3.4 布局稳定性

- 指派面板在 `idle / dispatching / success / error` 下保持稳定尺寸；
- 等待和结果区域预留固定或最小高度，状态切换不得推动员工广场大幅跳动；
- 内容超过可用高度时在面板内部截断或滚动；
- 不允许绝对定位内容覆盖分类筛选、员工卡片或页面其他控件；
- 移动端允许自然换行，但不能造成按钮、输入框和状态文字重叠。

## 4. 首页默认问题

### 4.1 数据来源

首页默认问题直接复用停用员工 `manager.quickQuestions`，不新增第二套字段。

- `/admin` 编辑任务经理时继续通过“快捷问题”字段配置；
- 首页读取任务经理的快捷问题用于需求示例；
- 普通业务员工的 `quickQuestions` 继续用于各自工作台左侧；
- 两者使用相同数据合同，但显示位置和用途不同。

公开员工接口当前只返回 `enabled` 员工，因此首页接口需要额外返回任务经理的公开快捷问题，不能把任务经理的 Prompt 或完整配置暴露为页面文案。

推荐接口示例：

```json
{
  "employees": [],
  "dispatchQuestions": [
    "比较两个方案并给出选择建议",
    "把一份资料整理成客户汇报",
    "检查项目问题并给出修复路径"
  ]
}
```

### 4.2 交互

- 首页只展示前 2 个默认问题；
- 两个问题纵向排列，每条独占一行；
- 点击后填入一句话指派输入框，不自动提交；
- 用户可以继续编辑，再点击“帮我指派”；
- 指派进行中禁用默认问题；
- 没有配置时不显示空容器或占位卡片；
- 文案较长时换行或截断，不撑破按钮。

## 5. 恢复对话内执行记录

### 5.1 展示原则

业务员工执行过程中，中间对话区恢复 0.3 改造前已有的详细执行展示。对话区与右侧执行区域使用同一份 `ChatTurn` 和 AG-UI 事件状态，不新增 runtime 或重复请求。

```text
对话区：查看这一步具体做了什么
右侧区：快速感知本轮进行到哪里
```

### 5.2 对话区详细内容

每个助手消息下可以展示：

- 阶段更新；
- 工具开始、执行中、成功和失败；
- 工具参数摘要；
- 工具进度；
- 工具结果和执行耗时；
- 权限拒绝；
- 子 Agent 步骤；
- 未知兼容事件；
- 文件、图片和 Artifact；
- 失败、取消和断线重连状态。

详细工具卡默认遵循：

- 当前运行工具自动展开；
- 已完成工具默认折叠成摘要；
- 失败和权限拒绝保持醒目；
- 参数和结果过长时使用内部滚动，不撑宽对话区；
- 不展示原始 reasoning 或隐藏 Prompt。

## 6. 右侧实时执行中心

### 6.1 命名

- 主标题：`实时执行中心`；
- 副标题：`能力调用与任务进度`。

不再使用过于技术化和信息不足的“执行舱 / 能力与实时事件”。

### 6.2 信息结构

```text
实时执行中心
  -> 能力配置
  -> 本轮状态
  -> 本轮事件时间线
  -> 固定终态
```

- 能力配置表示员工被配置为具备什么；
- 本轮时间线只展示真实收到的 Evo-Harness 事件；
- Skill 没有真实调用事件时只出现在能力配置区；
- 不从回答文本猜测 Skill 是否被调用。

### 6.3 长度约束

右侧区域不得随事件数量无限增长：

- 整体高度受工作台可视区域约束；
- 能力配置区域最多显示两行，超出时折叠为“查看全部能力”；
- 本轮事件区使用独立滚动容器；
- 默认显示当前事件和最近 8 至 12 条事件；
- 更早事件通过“查看全部执行记录”展开，不继续向下撑开页面；
- 当前运行事件自动保持可见；
- 已完成工具收敛为单行摘要；
- 终态固定显示在事件区域末端，不重复追加多个“已完成”；
- 新任务开始时右侧切换到新一轮，不把历史任务持续堆叠在当前时间线。

## 7. 工具产品化命名

前台主名称使用业务可理解的表达，真实底层工具名保留为次要信息、详情或 Tooltip，保证演示效果与事实可追溯性同时存在。

| 底层工具名 | 前台主名称 | 图标建议 |
| --- | --- | --- |
| `read` | 读取资料 | `FileSearch` |
| `write` | 更新工作文件 | `FilePenLine` |
| `bash` | 执行自动化 | `Terminal` |
| `send` | 交付文件 | `Send` |
| `memory_search` | 检索工作记忆 | `Brain` |
| `memory_get` | 读取记忆内容 | `BookOpen` |
| `vision` | 视觉理解 | `Eye` |
| `web_search` | 检索公开信息 | `Search` |
| 未识别工具 | 执行工具 | `Wrench` |

约束：

- 不把通用 `write` 固定命名为“生成报告”，避免夸大实际行为；
- 对话详细卡可以显示“更新工作文件 · write”；
- 右侧摘要只显示产品化主名称；
- 工具映射集中维护，不能在多个组件分别写一套名称；
- 未识别工具必须正常渲染，不能导致界面报错。

## 8. 多彩语义视觉

实时执行中心使用小面积、高识别度的多彩语义配色，提升客户演示时的动态感。颜色服务于能力类型和状态，不使用全栏渐变或无意义装饰。

### 8.1 能力类型

| 类型 | 主色方向 | 用途 |
| --- | --- | --- |
| 原子能力 `tool` | 亮蓝 | 图标底、能力标识 |
| `skill` | 洋红或珊瑚红 | 图标底、Skill 标识 |
| `knowledge` | 青绿 | 图标底、知识标识 |

### 8.2 执行状态

| 状态 | 语义色 |
| --- | --- |
| 等待 | 中性灰 |
| 审查中 / 执行中 | 亮蓝 |
| 等待用户确认 | 琥珀黄 |
| 成功 | 绿色 |
| 失败 / 拒绝 | 红色 |
| 文件产物 | 青色 |
| 取消 / 停止中 | 橙色 |

### 8.3 视觉边界

- 高饱和色只用于图标底、状态轨、当前事件、终态和小标签；
- 背景与正文继续保持安静、清晰和高对比；
- 不使用彩虹渐变、紫白大渐变、光球或闪烁装饰；
- 动画只用于 Loader、事件进入、当前状态和推荐聚焦；
- 已完成状态停止循环动画；
- 遵守 `prefers-reduced-motion`；
- 颜色之外同时使用图标和文字表达状态，不能只靠颜色区分。

## 9. 管理页增量

管理页不新增新的配置模型，只确认以下现有字段用途：

- `manager.quickQuestions`：首页一句话指派默认问题；
- 普通员工 `quickQuestions`：员工工作台左侧快捷问题；
- `capabilities`：实时执行中心的能力配置；
- `capabilities.name`：前台能力名称；
- `capabilities.kind`：能力类型与颜色；
- `capabilities.icon`：受控 Lucide 图标。

管理页应在编辑任务经理时提示“该员工的快捷问题会展示在首页任务调度台”，避免管理员不理解字段用途。

## 10. 明确不做

- 任务经理推荐的真实 SSE 或 AG-UI 流式传输；
- 为首页等待阶段新增第二套后端事件协议；
- 新增首页问题表、数据库或独立配置文件；
- 在右侧保留所有历史任务的完整时间线；
- 伪造 Skill 调用、工具结果或执行耗时；
- 展示原始 reasoning、系统 Prompt 或内部绝对路径；
- 重新引入 assistant-ui、CopilotKit 或第二套消息状态。
