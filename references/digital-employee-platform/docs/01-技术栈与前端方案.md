# 技术栈与前端方案

> 版本：v2.1（主体平台复核：2026-08-26）。这是本项目的技术细节与默认值；真正建项目时仍以
> lockfile、peerDependencies 和官方变更记录再次核验。

## 一句话结论

本项目采用一条有边界的混合路线：

```text
主体平台：dsh-v0.1.1-rc.2（Cordis profile/plugin/Web）
产品前端：dsh client slots 优先；独立管理页面才使用 Next.js App Router + React + TypeScript strict
Tailwind CSS v4 + shadcn/ui（默认页面与源码层）
Ant Design 6（复杂企业能力的隔离适配层）
assistant-ui（需要完整聊天 UX 时）
CopilotKit + AG-UI + A2UI v0.9.1 + 受控 BYOC Catalog
TanStack Query + React Hook Form + Zod 3.25.76
Recharts/Tremor（普通图表）+ Apache ECharts（复杂图表）
Lucide（默认图标）+ Motion（默认动效）
Three.js + React Three Fiber + drei（按需 3D）
Vitest/RTL + Playwright + Storybook + axe
```

执行边界固定为 `ExecutionProvider -> CowAgent`（CowAgent 当前可替换）；Loop 只保留一个 owner，优先验证
LoopX 的 dsh 插件。dsh 已有的 Session、Goal、Jobs、Schedule、Workflow、Approval、Storage、Web slots 和
社区插件优先复用，不另造同类平台。

这套路线把“让 AI 容易生成”和“不要重复造企业组件”同时满足：AI 默认读取项目内的 shadcn 源码、
tokens、Storybook 和语义组件；复杂 Table/Tree/筛选等能力复用 AntD，但不能把 AntD API 散落到业务层。

## 需求基线

- 学习者是后端转全栈，需要掌握足以审查 AI 前端方案的术语、状态模型、数据流和质量标准。
- 实践对象是企业/B 端交互式 UI，不能手写基础按钮、弹窗、表格、表单、反馈和可访问性行为。
- Agent 驱动的动态 UI 是硬需求；协议要可控、可测试、可恢复，不能让模型直接执行任意 JSX/JavaScript。
- 固定页面和 Agent 动态 UI 都要支持，不能把所有页面强行改成 A2UI。
- 视觉、图表、图标、动效、3D 都要有明确入口，但不因为“完整”而一次安装所有专业依赖。

## 选型原则

1. 先按职责分层，再按包名选型。组件库、图表库、图标库、动效库和 Agent 协议不是同一层。
2. 默认选择 AI 能读懂、源码可验证、示例和约束清楚的方案。
3. 复杂能力优先复用成熟引擎；项目层负责语义封装、状态、权限和验收，不复制引擎内部实现。
4. 混合必须以“边界隔离”为前提：同一业务组件只能有一个主要视觉实现，第三方 API 不向上泄漏。
5. Stars、下载量和博客观点只能作为影响力信号；官方规范、源码、issue 和可运行验证优先。

## 完整技术路线

### 应用、运行与部署

- dsh 主体锁 `dsh-v0.1.1-rc.2`，Node.js/pnpm/profile/plugin tarball 一起锁定；插件先做 artifact/profile/runtime
  smoke，再进入离线镜像。
- dsh 内嵌页面优先走其 client slots、client modules 和 WebServer；只有独立信息架构确实超出 dsh shell 时，
  才增加 Next.js App Router、React 19、TypeScript strict 的独立前端。两者不各自维护一套会话、任务或权限状态。
- Server Components 负责页面壳和服务端边界；表单、聊天、A2UI 和浏览器 API 明确使用 Client Component。
- 全离线/内网自托管为默认：Node/Docker/本地 Python 服务可独立运行；Vercel、托管 Agent runtime
  和外部遥测只能作为未来可选适配，不是运行前提。正式离线交付还需提前准备依赖镜像、模型服务、
  npm/PyPI 缓存和升级包。
- REST/JSON 为领域 API 默认；已有 OpenAPI 时用 `openapi-typescript`/`openapi-fetch`，避免重复 DTO。
- `ExecutionProvider` 是业务执行唯一入口；当前实现为 `CowAgentExecutionProvider`，以后替换 Harness 只新增
  provider，不改产品组件、A2UI Catalog 或 Loop 状态模型。

### 基础视觉和行为层

- `tailwindcss@4`：项目 token、布局和低级样式；不把任意长 Tailwind class 直接暴露给 Agent。
- `shadcn/ui`：源码复制到项目的基础组件，当前新项目默认使用 Base UI 行为基元；Radix flavor 仍作为成熟兼容选项。源码、stories 和 token 是 AI 的主要上下文。
- `class-variance-authority`、`clsx`/`tailwind-merge`：项目级变体和 class 合并。
- 组件优先从 `components/ui` 或 `components/domain` 导入，禁止业务代码直接从 registry 网址复制后不审查。

### 复杂企业能力隔离层

- `antd@6` 只用于复杂 `DataTable`、`Tree`、`TreeSelect`、高级筛选、批量编辑等 shadcn 组合成本明显过高的场景。
- 每个 AntD 能力都包装成项目级组件，例如 `EnterpriseTable`、`EnterpriseTree`、`TaskFilters`；业务层不依赖 `TableProps`。
- AntD 通过独立 provider、CSS layer、token bridge 和 Storybook stories 隔离；不在同一基础按钮、表单或弹窗体系里自由混搭。
- `@ant-design/icons` 只在 AntD 适配层内部使用，不作为全项目第二套默认图标。
- 只有当复杂网格达到虚拟滚动、树数据、行分组、Excel 编辑等要求时，才评估 AG Grid，并单独确认 Enterprise 许可。

### AI UI、runtime 与协议

- `assistant-ui`：需要完整聊天 UX 时的默认聊天组件层，提供可组合 Thread、Message、Composer、tool call、审批、附件和无障碍体验，且有 shadcn/Base UI 风格和 AG-UI 适配器。
- `CopilotKit`：Agent 会话、前端 actions、共享状态和 A2UI 接入的 runtime；不把它当作普通组件库。
- `AG-UI`：Agent 与应用间的双向事件、状态、工具和流式传输契约，默认用 SSE。
- `A2UI v0.9.1`：声明式 UI 消息协议；v1.0 仍是 candidate，不作为默认生产协议。
- 受控 BYOC Catalog：只暴露项目语义组件和明确的 Zod props schema；不开放任意 JSX、CSS、第三方 props 或事件处理器。
- `Ant Design X 2`：保留为 AntD 隔离区域的 AI 视觉候选；不与 assistant-ui 同时作为全局聊天层安装。若产品整体改为 AntD 视觉，再切到 AntD X。
- `@ai-sdk/react`：只有后端明确采用 Vercel AI SDK，或需要其 `useChat`/structured stream 时才接入；它不是 AG-UI/A2UI 的替代品。

### 数据、表单和 schema

- `@tanstack/react-query`：服务端数据、缓存、失效、重试和任务轮询；局部开关、草稿、弹窗使用 `useState`/`useReducer`。
- `react-hook-form`：默认表单状态和非 AntD 控件组合；配合 `@hookform/resolvers`。
- `zod@3.25.76`：API、表单提交、Catalog props 的运行时边界。当前不把 Zod 4 作为 A2UI 默认 schema，避免绑定器兼容问题。
- 同一表单不能同时由 RHF 和 AntD Form 维护同一字段；复杂 AntD 组件作为 RHF `Controller` 受控适配。
- URL 筛选、分页、排序优先使用 `searchParams`；复杂类型化 URL 状态再引入 `nuqs`。

### 图表

- 默认常规图表：shadcn Chart 源码模式 + `recharts`（折线、柱状、面积、饼、常规组合图）。Tremor 作为可复制的 dashboard 模式来源，不再额外引入一套运行时抽象。
- 复杂图表：`echarts` + `echarts-for-react`，用于地图、Sankey、Treemap、热力图、时间轴、大数据量和复杂交互；按模块注册以控制 bundle。
- 不默认同时安装 Recharts、Tremor、Ant Design Plots、Nivo、visx；项目只保留一个普通图表默认实现，复杂场景才进入 ECharts。
- A2UI Catalog 只允许语义图表组件（如 `KpiChart`、`TrendChart`），由前端校验数据和 option 白名单；Agent 不直接生成任意 ECharts option。

### 图标

- 默认：`lucide-react`。Lucide 是 shadcn 生态常用的 1600+ SVG 图标集，ESM tree-shaking、TypeScript 和可访问性入口清晰。
- 检索/补充：Iconify 用于搜索 200+ 图标集和发现名称；生产默认不依赖公共 API 运行时，必要图标应固化成本地包或受审查 SVG。
- Tabler Icons 是可接受的第二候选（6100+、MIT），但不与 Lucide 在同一语义层混用；只有品牌或填充图标缺口时局部引入。
- AI 规则：图标只接受组件对象或受控名称映射，优先从项目 `icon-library.ts` 选择现有图标，禁止 AI 手写新的内联 SVG。

### 动效与 3D

- 基础状态变化：CSS transition/animation，优先动画 `opacity`、`transform` 等低成本属性。
- React 交互动画：`motion`（原 Framer Motion），用于布局、手势、presence、spring 和状态驱动动画；默认按需导入。
- 复杂时间轴、滚动叙事、SVG morph：按需 `gsap`/`@gsap/react`；它是 imperative 工具，不作为所有组件的默认依赖。
- 低成本列表增删可选 `@formkit/auto-animate`，但不能替代需要明确状态和可访问性设计的动画。
- 3D 按需：`three` + `@react-three/fiber@9` + `@react-three/drei`；后处理再加 `@react-three/postprocessing`。
- 3D 场景必须是独立 Client Component，通过 `next/dynamic({ ssr: false })` 或等价边界加载，设置帧率、资源、移动端和 `prefers-reduced-motion` 预算；不把 Three.js 放入默认首屏包。

### 测试和验证

- Vitest + React Testing Library：状态转换、组件行为、Catalog schema、事件回传。
- Playwright：真实浏览器流程、SSE/AG-UI、响应式、键盘焦点和审批闭环。
- Storybook：组件状态矩阵、项目级 API、视觉和 a11y；接入 Storybook MCP 给 Agent 读取 stories。
- MSW：REST、SSE/AG-UI 和错误/延迟场景的可控 mock。
- `axe`/Storybook a11y、Chrome DevTools MCP：运行时 Console、网络、DOM、布局和性能事实。

## 组件边界图

```text
固定页面
  -> shadcn/ui + Tailwind（默认）
  -> 项目 domain components（统一语义、状态、权限和验收）
  -> AntD adapter（仅复杂 Table/Tree/筛选等）

AI 聊天
  -> dsh conversation slots / assistant-ui（聊天 UX，二选一并共用一个状态 owner）

Agent 动态 UI
  -> CopilotKit runtime
  -> AG-UI 事件
  -> A2UI v0.9.1 消息
  -> 受控 Catalog
  -> shadcn 项目组件或 AntD adapter
```

这里的“按需”不是不支持，而是避免第一天把多个相互重叠的抽象同时交给 AI，导致 bundle、主题、API 和验收边界失控。

## 关键兼容性约束

- AntD + Tailwind 可以混用，但必须处理 CSS layer、reset、token、portal、z-index、SSR 和主题；混合只发生在项目组件边界。
- A2UI v0.9.1 是当前生产版本，v1.0 是 candidate；版本号不能用 npm renderer 版本替代。
- CopilotKit/A2UI 当前统一使用 `zod@3.25.76`。升级 Zod 4 必须先有官方兼容矩阵、动态绑定回归测试和依赖树检查。
- R3F v9 与 React 19 配对；Three.js、R3F 和后处理都属于浏览器 Client 边界。
- 图表和图标必须考虑 SSR/hydration、按需加载、a11y、主题 token 和视觉回归，不能只验证“能渲染”。

## 为什么这不是“组件库堆砌”

这里实际只保留三种职责：

1. **默认源码层**：shadcn/Tailwind，负责大多数固定 UI 和 AI 可读性。
2. **专业引擎层**：AntD、ECharts、R3F 等，只在它们确实省掉大量重复实现时接入。
3. **协议/验证层**：CopilotKit、AG-UI、A2UI、Catalog、测试工具，负责 Agent 交互和质量边界。

业务代码永远依赖项目级语义组件，不依赖这些第三方库的原始 API。这样既能复用成熟实现，也能让 Agent 看到稳定、短小、可验证的上下文。

## 复核触发条件

1. 第一条切片已验证 shadcn-style 项目组件 + RHF 能覆盖任务表单、审批和错误状态；复杂结果表已通过 `EnterpriseTable` 进入 AntD adapter。
2. 普通图表是否出现超过 Recharts 的地图、关系图或大数据需求；若没有，不引入 ECharts。
3. 本条 runtime spike 由 CopilotKit 统一负责会话/工具事件；若后续引入 assistant-ui，只能作为视图层并复用同一状态 owner。
4. 动效或 3D 是否是当前产品价值的一部分；若不是，保持按需依赖。
5. 真实 Figma 资产出现时，再接 Figma MCP + Code Connect；没有设计源文件时不虚构设计流程。

## 证据索引

- [Vercel Chatbot](https://github.com/vercel/chatbot/)：高星 Next.js AI 项目，使用 AI SDK、shadcn、Tailwind 和 Radix。
- [assistant-ui](https://github.com/assistant-ui/assistant-ui)：高星 React AI chat 库，提供 shadcn 风格组件、生成式 UI 和 AG-UI 适配。
- [LobeHub AGENTS.md](https://github.com/lobehub/lobehub/blob/main/AGENTS.md)：真实 AI 产品采用 base-ui -> 自有 UI -> AntD 的优先级分层。
- [shadcn Chart](https://ui.shadcn.com/docs/components/radix/chart)：源码式图表组件，基于 Recharts v3，不锁死底层 API。
- [Recharts](https://recharts.org/en-US/)：React 组合式 SVG 图表。
- [Apache ECharts](https://echarts.apache.org/en/index.html)：20+ 图表类型、Canvas/SVG、渐进式渲染和复杂分析。
- [Lucide React](https://lucide.dev/guide/react/)：tree-shakable、TypeScript、可访问的 React 图标。
- [Iconify React](https://iconify.design/docs/icon-components/react/)：按需搜索 300,000+ 图标，但 Next 下公共 API 运行时有 hydration/延迟约束。
- [Motion for React](https://motion.dev/docs/react)：React 原生声明式动画、手势、布局和 spring。
- [GSAP](https://gsap.com/docs/v3/)：复杂时间轴、滚动和 SVG 动画的成熟 imperative 工具。
- [React Three Fiber](https://r3f.docs.pmnd.rs/getting-started/introduction)：React 的 Three.js renderer，并提供 MCP 文档入口。
- [drei](https://github.com/pmndrs/drei)：R3F 常用相机、控制器、加载器和性能 helper。
- [A2UI](https://a2ui.org/)：v0.9.1 current production，v1.0 candidate；生产应用应定义自己的 Catalog。
- [AG-UI](https://docs.ag-ui.com/introduction)：Agent 与用户界面的事件和状态协议；A2UI 是其可组合的生成 UI 层。
