# 完整前端能力矩阵与混合路线决策

> 这是选型的速查页。详细证据见[技术栈深度调研与 AI 协作范式](./技术栈深度调研与AI协作范式.md)。

## 最终路线

```text
Next.js + React + TypeScript strict
  -> Tailwind CSS v4 + shadcn/ui（默认源码层）
  -> 项目语义组件（统一状态、权限、tokens、a11y）
  -> AntD 6 adapter（复杂企业能力）
  -> 专业能力 adapter（Recharts/ECharts、Lucide、Motion、R3F）
  -> CopilotKit + AG-UI + A2UI + 受控 Catalog
```

## 能力矩阵

| 能力 | 解决什么问题 | 默认方案 | 按需升级 | 不让 AI 做什么 |
| --- | --- | --- | --- | --- |
| 页面基础 | 布局、按钮、弹窗、输入、导航、主题 | Tailwind v4 + shadcn/ui（Base UI flavor） | Radix flavor（已有项目兼容） | 不直接粘贴未经审查的 registry 代码 |
| 企业复杂控件 | Table、Tree、筛选、批量编辑、虚拟滚动 | 项目 adapter + AntD 6 | AG Grid（确认许可） | 不泄漏 `TableProps` 和内部 DOM |
| 表单 | 字段状态、校验、提交和错误 | React Hook Form + Zod 3.25.76 | AntD 控件作为受控 field | 不让 RHF 和 AntD Form 双重维护字段 |
| 服务端数据 | 缓存、失效、重试、轮询 | TanStack Query | 仅按后端协议增补客户端 SDK | 不用全局 UI store 保存服务端数据 |
| 聊天 UX | 流式消息、工具调用、附件、审批 | assistant-ui（需要时） | AntD 全局项目用 AntD X | 不维护两份会话状态 |
| Agent 事件 | 流式事件、工具、共享状态 | AG-UI over SSE | WebSocket（高频双向时） | 不把事件当作视觉组件 |
| Agent 动态 UI | 声明式 surface 和组件树 | A2UI v0.9.1 + BYOC Catalog | 新协议版本通过适配层升级 | 不执行任意 JSX/JS/CSS |
| Agent runtime | 会话、frontend actions、Catalog 接入 | CopilotKit | 后端自选 LangGraph/AI SDK | 不把 runtime 当设计系统 |
| 普通图表 | 常规统计 dashboard | Recharts + shadcn Chart/Tremor 源码模式 | - | 不直接暴露任意 chart option |
| 复杂图表 | 地图、Sankey、Treemap、大数据 | ECharts adapter | mcp-server-chart 仅作辅助 | 不让模型无限组合图表配置 |
| 图标 | 一致、可复用、无需手写 SVG | Lucide React | Tabler/品牌图标局部固化；Iconify 搜索 | 不生成新的内联 SVG |
| 普通动效 | hover、展开、状态变化 | CSS | Motion | 不为了“炫”加入无意义动画 |
| 复杂动效 | 时间轴、滚动叙事、SVG morph | GSAP 按需 | - | 不在 React 中无边界操作 DOM |
| 3D | WebGL 场景、3D 主视觉 | Three + R3F + drei 按需 | postprocessing/physics | 不让 Agent 直接生成未审查 WebGL 场景 |
| 质量验证 | 编译、行为、浏览器、视觉、a11y | Vitest/RTL + Storybook + Playwright + axe | Chrome DevTools MCP | 不接受“能运行”作为完成证据 |

## 哪些依赖第一天不装

```text
MUI、PrimeReact、第二套完整设计系统
Tremor runtime、Ant Design Plots、Nivo、visx（普通图表先用 Recharts）
Tabler + Iconify runtime（Lucide 足够时不叠加）
GSAP、Three.js、R3F、postprocessing（没有真实需求时）
assistant-ui、AntD X、Vercel AI SDK UI 三者同时安装
AG Grid（AntD adapter 尚未证明不足时）
```

## 混合的四条硬规则

1. **一个语义组件，一个主实现**：业务层只依赖 `EnterpriseTable`、`TrendChart`、`AgentThread` 等项目组件。
2. **第三方 API 不越过 adapter**：AntD/ECharts/R3F 的复杂 props 在 adapter 内被收窄、校验和测试。
3. **动态 UI 只使用 Catalog**：Agent 看到的是组件说明、schema、示例和事件白名单，不是源代码执行权限。
4. **所有复杂能力按需加载**：通过动态 import、模块化注册和 Client boundary 控制 bundle、SSR 和性能。

## 与 AI 沟通的最短表达

```text
默认用 shadcn/ui + Tailwind，不要直接引入另一套基础设计系统。
复杂 Table/Tree 只通过 Enterprise adapter 使用 AntD。
图表先用项目 TrendChart/KpiChart；复杂需求再用 ECharts adapter。
图标从 icon-library.ts 选择 Lucide，不要手写 SVG。
动画先 CSS，再 Motion；GSAP 和 Three.js 只有在需求明确时使用。
A2UI 只允许受控 Catalog 组件，不能生成任意 JSX、CSS、图表 option 或 WebGL。
先定义状态、事件契约、错误状态和验收，再开始写组件。
```
