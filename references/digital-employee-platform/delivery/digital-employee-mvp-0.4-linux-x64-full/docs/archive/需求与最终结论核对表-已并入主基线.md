## 一、先给结论

**需求已经明确，边界级架构已经收敛；还没有把未经运行验证的插件和 CowAgent 接入写成“生产完成”。**

当前目标不是从零开发一个新 Agent 平台，而是：

```text
dsh-v0.1.1-rc.2（主体平台 / 插件宿主 / 管理入口）
  + 已有 dsh/社区插件（按职责复用）
  + 一个 Loop owner（优先验证 LoopX dsh plugin）
  + ExecutionProvider（当前实现 CowAgent，未来可替换）
  + 自有数字员工产品页面 + AG-UI/A2UI
```

其中“主体平台已定”和“某个插件已经在该版本开箱可用”是两件事，必须分开记录。

## 三、已经“定下来”的和还要“跑出来”的

### 已定下来的架构边界

- 主体：官方 dsh `dsh-v0.1.1-rc.2`。
- 执行：每条 run 只有一个 `ExecutionProvider`；当前实现是 CowAgent。
- 产品：自有管理台，参考多个成熟项目，不整仓复制。
- 动态 UI：AG-UI + A2UI + 受控 Catalog，不重写 renderer。
- Loop：运行时只允许一个 Loop owner 和一个任务事实源。
- 部署：air-gapped、内网、低并发、固定制品。
- 复用：现成能力优先，兼容问题做最小 patch。

### 必须通过验证才能进入真实运行

1. LoopX dsh plugin 在 dsh `rc.2` 的 artifact/profile/runtime/browser smoke。
2. CowAgent `ExecutionProvider` 的 `start -> runId -> ordered events -> terminal result`，以及 inspect/cancel/
   timeout/resume/idempotency/permission 语义。
3. 一条真实 SOP 的 `Goal -> bounded turn -> validator/Audit -> evidence -> next/stop` 闭环。
4. 断网、重启、重复唤醒、人工 Gate 和外部 effect readback。
5. 插件依赖闭包、许可证/SBOM、镜像、遥测关闭和网络审计。

这些是工程证据，不是还在摇摆的产品需求。未通过时，优先用 Mock Provider 继续验证 dsh/前端结构，不能
通过逆向 CowAgent Web 私有接口或同时引入第二套 Harness 来掩盖缺口。

## 四、插件“有人做了”应怎样理解

这个判断**大方向正确**，但准确说法是：横向功能大多已经有实现，当前组合仍要做版本和执行边界核验。

| 类别 | 已有实现 | 我们的动作 |
| --- | --- | --- |
| dsh 主体能力 | Session、Goal、Jobs、Schedule、Workflow、Approval、Storage、Web slots | 直接采用 `rc.2`，不重写 |
| 传输与动态 UI | `dsh-ag-ui`、Valuz A2UI、受控 Catalog | 安装/构建/smoke；必要时做兼容 patch |
| 长效 Loop | `dsh-loopx-plugin`、LoopX core | 优先验证 dsh 插件；替换默认 dsh Agent 执行 seam |
| 看板与台账 | `dsh-taskboard`、`dsh-task-center` | 借 UI/ledger/状态语义，替换直接 `ctx.agents` 执行调用 |
| 审核与后台能力 | `dsh-auto-review`、`dsh-background-agents` | 按需求选择，不让它们形成第二业务执行器 |
| 工程范式 | LongHorizon MEA、Symphony reconciliation/runner | 只吸收设计和验收方法，不并装成多个状态源 |
| 在线发现 | `dsh-market` | 只在联网构建区发现；内网使用审核后的静态 manifest/tarball |

当前已知的兼容风险：LoopX 插件主要锁 dsh `rc.7/rc.8`；Valuz A2UI 主要按旧 rc 验证；部分 taskboard/审核
插件会默认创建 dsh Agent；`dsh_workflow` 的公开兼容基线是旧快照。它们都适合“复用后验证/薄适配”，不能
直接写成 `rc.2 + air-gap + CowAgent` 已开箱通过。

## 六、避免再次跑偏的短句

> 数字员工是产品表达；dsh 是主体与插件宿主；Loop 是长效控制；ExecutionProvider 是可替换执行边界；CowAgent 是当前真正干活的实现。

> 复用现成插件，不等于跳过版本、离线和执行边界验证；需要自研的是薄适配和业务领域，不是再造平台。
