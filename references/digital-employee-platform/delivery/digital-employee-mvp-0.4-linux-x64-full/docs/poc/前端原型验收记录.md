- 任务输入使用 React Hook Form + Zod 校验。
- 状态集中在 reducer，明确 `idle/submitting/running/readyForApproval/approving/approved/rejected/empty/error`。

- CopilotKit v2 runtime route 已接入；本地 `AbstractAgent` 发送 AG-UI 事件和 A2UI v0.9.1 operations。
- A2UI 使用受控 Catalog，动态绑定字段通过 Zod 3 动态 schema 解析后再交给 React renderer。
- 聊天 run 会生成并弹出受控 `ApprovalDialog`；批准/退回由 A2UI action schema 绑定，经 CopilotKit
  action bridge 作为 `forwardedProps.a2uiAction` 发起下一次 Agent run，Agent 返回确认消息。
- 页面覆盖 loading、progress、success、empty、error、retry、approval、reject 和 reset。
- CSS 已包含响应式布局、焦点样式和 `prefers-reduced-motion`。

## 本阶段的验证策略

1. 先用 reducer 单测验证状态转换、事件去重和 request version。
2. 用 RTL 验证表单校验、提交中禁用、结果和审批按钮。
3. 用 Playwright 验证真实浏览器中的提交、进度、审批、拒绝、重置和窄屏布局。
4. 用 Storybook 固化组件状态矩阵，并用 Playwright + axe 检查语义和焦点。
5. 用 MSW 独立验证 SSE/AG-UI transport 的延迟、重复事件、重试和错误；runtime 浏览器用例再验证真实 renderer 链路。

## 当前已知限制

- 当前环境同时存在 Windows Node/pnpm 和 WSL Node；使用错误平台的 `node_modules` 会触发 Rolldown、esbuild、Oxc 或 Next SWC 原生 binding 错误。验证时已用对应 Linux binding 完成测试和 Storybook，标准项目仍应在单一平台重新安装依赖。
- WSL 调用 Windows pnpm 时，pnpm store 的重命名被 Windows 权限拒绝；因此本次不把 `pnpm install` 的环境失败误判为项目失败。正式仓库应在固定 Linux/CI 环境生成并提交完整 lockfile。
- 当前页面保留项目 CSS/tokens 作为视觉实现，Tailwind v4 已加载并通过构建；后续新增组件仍按 shadcn/Tailwind 源码模式落地。
- `next.config.ts` 已使用 server deployment；接入真实模型时仍需补齐鉴权、权限、断线重连、幂等和观测。
- `runMockAgent` 的事件延迟只用于演示；真实 Agent 需要处理断线、重连、服务端幂等和权限。
- `TaskSurface` 是业务工作流的静态受控 surface；runtime spike 已覆盖动态绑定和 action event，但生产 Catalog 仍需要版本升级、未知节点、权限和幂等策略。
