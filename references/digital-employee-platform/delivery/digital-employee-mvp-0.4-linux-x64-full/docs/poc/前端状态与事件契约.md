# 第一条切片：状态与事件契约

> 用途：这是实现“Agent 任务处理与审批”前交给 Agent 的最小设计契约。它先固定状态和边界，再决定组件细节。

## 1. 三类状态不能混在一起

| 状态类别 | 示例 | 归属 | 持久化/缓存 |
| --- | --- | --- | --- |
| 局部 UI 状态 | 表单草稿、拒绝弹窗是否打开、当前选中行 | React 组件/页面 | 通常不持久化 |
| 服务端任务状态 | taskId、任务阶段、结果、错误、审批结果 | 后端任务 + TanStack Query | 可缓存、可重新获取 |
| Agent 事件流状态 | 已收到哪些进度事件、最后序号、连接是否结束 | AG-UI adapter | 运行期间维护，结束后归档到任务结果 |

`A2UI` 消息不是第四种业务状态。它是 Agent 对“应该显示哪些受控组件”的声明，渲染结果仍然由 React 状态决定。

## 2. 页面状态机

```text
idle
  -> submitting
  -> running
  -> readyForApproval
  -> approving
  -> approved

running -> empty
running -> error
error -> submitting
readyForApproval -> rejected
readyForApproval -> submitting（重新运行）
approved -> submitting（重新运行）
rejected -> submitting（重新运行）
```

### 不变量

- `submitting`、`running`、`approving` 时不能重复发起同一个用户操作。
- `readyForApproval` 之前不能批准或拒绝。
- `approved`、`rejected` 必须有对应的 taskId 和结果版本。
- `error` 必须保留可理解的错误信息和 retry 入口，不把错误吞成空白页面。
- `empty` 不是 `error`；请求成功但没有可审批结果时使用 `empty`。
- 页面显示由状态派生，不使用 `isLoading && isError && isApproved` 这类互相矛盾的布尔组合。

## 3. 领域数据契约

```ts
type TaskInput = {
  instruction: string;
};

type TaskStatus =
  | "idle"
  | "submitting"
  | "running"
  | "readyForApproval"
  | "empty"
  | "error"
  | "approving"
  | "approved"
  | "rejected";

type TaskRow = {
  id: string;
  label: string;
  value: string;
};

type TaskResult = {
  taskId: string;
  version: number;
  summary: string;
  rows: TaskRow[];
};

type TaskState = {
  status: TaskStatus;
  taskId?: string;
  progress?: number;
  phase?: string;
  result?: TaskResult;
  error?: { code: string; message: string; retryable: boolean };
  eventSequence: number;
};
```

实现时用 Zod 3.25.76 在 API/事件边界解析输入，TypeScript 类型只描述通过解析后的可信数据；不要把模型返回的
任意 JSON 直接当成 `TaskResult`。

## 4. 应用级事件封装

AG-UI SDK 的具体事件名由接入版本决定；页面内部先统一成应用事件，避免组件直接依赖协议细节：

```ts
type AppAgentEvent =
  | { type: "task.started"; taskId: string; sequence: number }
  | { type: "task.progress"; taskId: string; phase: string; progress?: number; sequence: number }
  | { type: "task.result"; taskId: string; result: TaskResult; sequence: number }
  | { type: "task.empty"; taskId: string; sequence: number }
  | { type: "task.failed"; taskId: string; code: string; message: string; retryable: boolean; sequence: number }
  | { type: "approval.succeeded"; taskId: string; version: number; sequence: number }
  | { type: "approval.rejected"; taskId: string; version: number; sequence: number };
```

adapter 只允许处理当前 `taskId` 且 `sequence` 大于已处理序号的事件。旧任务、重复事件和过期结果必须丢弃，
避免断线重连或延迟事件覆盖当前页面。

## 5. A2UI Catalog 边界

Catalog 只暴露语义化组件，不暴露 `antd` 原始 props：

| Catalog 组件 | 允许表达的内容 | 允许的用户事件 |
| --- | --- | --- |
| `TaskForm` | 任务说明和有限参数 | `task.submit` |
| `StatusBadge` | 当前阶段和状态色 | 无 |
| `ResultPanel` | 摘要、结果版本和提示 | 无 |
| `ResultTable` | 已校验的 `TaskRow[]` | `row.select`（可选） |
| `ApprovalActions` | 批准/拒绝/重试 | `approval.approve`、`approval.reject`、`task.retry` |
| `TaskTimeline` | 已排序的进度事件 | 无 |
| `EmptyState` | 无结果说明 | `task.retry`（可选） |
| `RetryAction` | 可重试错误 | `task.retry` |

每个组件需要：

- Zod props schema 和默认值；
- 可见状态、loading、disabled、empty、error 规则；
- 事件名称、payload 和权限检查；
- Storybook story、RTL 交互测试、Playwright 关键流程和 a11y 检查。

## 6. 组件边界

```text
TaskWorkspace
  ├─ TaskForm                  # 局部草稿，提交事件上报
  ├─ TaskStatus / StatusBadge  # 从 TaskState 派生
  ├─ TaskTimeline              # 只读事件列表
  ├─ ResultPanel
  │   └─ ResultTable            # 默认项目表格；复杂网格时由 EnterpriseTable adapter 实现
  └─ ApprovalActions            # 只发送领域事件，不直接改结果数据
```

`TaskWorkspace` 持有任务状态和事件 adapter；子组件通过 Props 接收数据，通过 callback 上报用户意图。
批准按钮不能直接把页面改成 `approved`，它必须触发批准请求，等待服务端/Agent 事件后再由状态更新页面。

## 7. 交互时序

```text
用户提交
  -> TaskWorkspace 校验 TaskInput
  -> status=submitting
  -> 创建 task / 建立 AG-UI 流
  -> 收到 started/progress，status=running
  -> 收到 result，解析并缓存 TaskResult
  -> status=readyForApproval
  -> 用户批准
  -> status=approving
  -> 收到 approval.succeeded
  -> status=approved
```

错误、空结果和重试都沿同一条状态路径处理；不要为每个异常另造一组互相独立的 boolean。

## 8. 第一轮实现顺序

1. 先用 Mock adapter 产生应用级事件，不接真实 Agent。
2. 用 shadcn/ui + React Hook Form + Zod 3.25.76 完成输入、提交和字段错误。
3. 用 `useReducer` 或明确的状态转换函数驱动 `TaskState`。
4. 用项目级 `ResultTable`、`TaskTimeline` 和 AgentThread 完成固定页面；只有复杂网格才接 AntD adapter。
5. 加入受控 A2UI Catalog，只渲染上述白名单组件。
6. 独立 runtime spike 已接入 CopilotKit + AG-UI + A2UI；业务状态机仍保留 Mock adapter，外部 Agent endpoint 再按生产鉴权与恢复契约接入。
7. 运行类型检查、RTL、Storybook、Playwright、a11y 和窄屏视觉检查。
