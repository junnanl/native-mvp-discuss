# 第一条垂直切片：Agent 任务处理与审批

## 目标

验证一条从用户输入到 Agent 反馈、A2UI 渲染、用户审批和质量验收的完整链路。业务工作流使用
确定性的 Mock Agent，另有独立 CopilotKit runtime spike 验证 AG-UI/A2UI 的真实客户端链路；外部
生产 Agent 服务不属于本切片范围。

## 用户与路径

用户是企业内部的任务处理人员。用户在工作台输入一条任务要求，提交后观察 Agent 的处理状态，
查看 Agent 返回的结构化结果，最后批准或拒绝建议。

```text
打开任务工作台
  -> 输入任务描述
  -> 提交
  -> 显示处理中和进度事件
  -> 渲染结果面板/结果表格
  -> 批准或拒绝
  -> 显示最终状态和可重试入口
```

## 页面组成

- `TaskForm`：任务描述、可选参数、提交按钮。
- `TaskStatus`：idle、submitting、running、success、empty、error、rejected。
- `ResultPanel`：Agent 的摘要、结构化字段和结果列表。
- `ApprovalActions`：批准、拒绝、重新运行。
- `EventTimeline`：展示 Agent 事件的时间顺序和当前阶段。

普通页面由 React 组件渲染；Agent 产生的动态部分通过受控 A2UI Catalog 映射到以上语义化组件。
Catalog 不开放任意 JSX、任意 JavaScript 或第三方库底层 Props。

## 状态模型

```text
idle
  -> submitting
  -> running
  -> readyForApproval
  -> empty
  -> error

error -> submitting（重试）
readyForApproval -> approving（批准或拒绝）
readyForApproval -> submitting（重新运行）
approving -> approved
approving -> rejected
approved -> submitting（重新运行）
rejected -> submitting（重新运行）
```

需要明确区分：

- 表单草稿是局部 UI 状态；
- Agent 任务和结果是服务端/任务状态；
- AG-UI 事件是处理过程中的事件流；
- A2UI 消息是受控的 UI 描述，不是任意代码执行入口。

## 最小数据契约

```ts
type TaskInput = {
  instruction: string;
};

type TaskResult = {
  summary: string;
  rows: Array<Record<string, string>>;
};

type TaskStatus =
  | "idle"
  | "submitting"
  | "running"
  | "readyForApproval"
  | "empty"
  | "error"
  | "approving"
  | "approved"
  | "rejected";
```

第一版只要求 Mock Agent 能发出：任务开始、进度更新、结果、错误、批准成功和拒绝事件。
真实后端认证、权限、持久化和复杂业务字段不进入第一条切片。

## 第一版技术边界

- Next.js App Router、React、TypeScript strict。
- Tailwind CSS v4 + shadcn/ui 作为默认视觉和源码层；复杂结果网格通过隔离的 AntD adapter 复用 AntD 6。
- React Hook Form 管理任务表单，Zod 3.25.76 校验提交数据和 A2UI/Catalog 边界；AntD 控件若引入则通过受控适配接入，不能双重维护字段。
- TanStack Query 管理任务请求和结果缓存；局部交互使用 `useState`/`useReducer`。
- 结果列表通过项目级 `EnterpriseTable` adapter 使用 AntD 6；业务层不直接依赖 AntD API，不预装 AG Grid。
- Mock Agent 负责状态机验收；独立 runtime spike 已接入 CopilotKit + AG-UI + A2UI，外部后端 endpoint 随后接入。

## 验收标准

- 输入为空时不能提交，并有可理解的错误提示。
- 提交后按钮、状态和时间线进入处理中；重复提交被正确处理。
- 能展示 success、empty、error、retry、rejected 等状态，状态之间没有互相矛盾的组合。
- 结果列表在桌面和窄屏下都可用，不因内容变化导致布局跳动。
- 批准和拒绝是明确的用户事件，结果不会只靠直接修改 DOM 更新。
- A2UI Catalog 只能渲染允许的语义化组件，并拒绝未知组件或非法字段。
- 通过 TypeScript、组件交互测试、Playwright 关键流程和 Storybook 状态检查。

## 本切片学习的前端概念

组件边界、Props、State、受控表单、状态机、派生数据、异步请求、loading/error/empty、事件契约、
服务端数据与 UI 状态、A2UI Catalog、响应式布局和可访问性。

## 完成后的选型复核

完成切片后只回答三个问题：

1. shadcn + RHF 是否足以覆盖普通页面、结果区和审批交互？
2. 是否出现必须引入 AntD adapter、AG Grid、ECharts 或其他专业库的真实缺口？
3. CopilotKit、AG-UI、A2UI 的事件和 Catalog 边界是否满足可测试、可维护要求；外部服务的恢复、鉴权和幂等留到部署集成阶段？
