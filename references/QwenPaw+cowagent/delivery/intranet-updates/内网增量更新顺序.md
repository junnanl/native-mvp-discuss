# Evo-Harness 内网增量更新顺序

## 更新包

必须按以下顺序部署：

1. `cowagent-site-update-v1.0.3-runtime-config.tar.gz`
2. `cowagent-site-update-v1.0.4-officecli-toolpack.tar.gz`
3. `cowagent-site-update-v1.0.5-html-report.tar.gz`
4. `cowagent-site-update-v1.0.6-mcp-ssh-manager.tar.gz`

每个更新包都会记录状态文件。后一个更新包检测不到前一个更新包的成功状态时会直接停止，不会跳过顺序继续安装。回滚必须按相反顺序执行。

## 一键部署四个更新

把整个 `intranet-updates` 目录复制到内网服务器后，在该目录执行：

```bash
bash deploy-all.sh
```

默认目标目录为：

```text
/opt/cowagent-offline
```

脚本依次完成外层和包内 SHA256 校验、解压、备份、更新、容器重启和验证。任何一步失败都会停止后续更新并明确报错。

默认会应用 `v1.0.3` 包内的现场模型配置。现场模型已经正确、只需要保留当前配置时使用：

```bash
PRESERVE_CURRENT_CONFIG=1 bash deploy-all.sh
```

## 验证

```bash
bash verify-all.sh
```

## 采集日志

```bash
bash collect-logs-all.sh
```

日志保存在：

```text
/opt/cowagent-offline/support-bundles
```

## 整体回滚

```bash
bash rollback-all.sh
```

整体回滚严格按 `v1.0.6 → v1.0.5 → v1.0.4 → v1.0.3` 执行。单独回滚较早版本时，如果后续版本仍处于已应用状态，脚本会拒绝执行。

`v1.0.6` 安装离线 MCP Toolpack、37 个默认启用的 SSH 工具、CowAgent MCP 配置和 SSH 连接管理 Skill，不包含 SSH 地址、账号、密码或私钥。部署后可直接在 CowAgent 对话中提供连接名称、IP、端口、账号和密码，由 CowAgent 自动保存；首次主机密钥自动记录，发生变化时需要用户确认后重新信任。

## 数据保护

更新和回滚都不会删除以下运行数据：

- 对话和长期记忆。
- 知识库。
- 上传文件和生成文件。
- 现场模型运行配置。
- 现场已有的其他 Skill。

`v1.0.3` 默认入口会使用包内已准备的内网模型配置，并在覆盖前备份现场配置。该包包含现场专用凭据，只能在受控内网和受控传输链路中保存，不得上传公开仓库或发送给无关人员。
