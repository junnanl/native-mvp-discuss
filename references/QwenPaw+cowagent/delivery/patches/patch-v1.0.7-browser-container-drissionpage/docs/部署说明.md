# 部署说明：patch-v1.0.7-browser-container-drissionpage

## 部署

```bash
# 1. 解压补丁包到现场可访问目录（内网受控链路传输）
tar -xzf patch-v1.0.7-browser-container-drissionpage.tar.gz
cd patch-v1.0.7-browser-container-drissionpage

# 2. 先校验（不改动任何文件）
TARGET_ROOT=/opt/cowagent-offline ./verify.sh   # 未安装时 verify 会失败，可跳过；安装后必须通过

# 3. 安装（自动备份、写状态文件、重启服务、跑验收）
TARGET_ROOT=/opt/cowagent-offline ./update.sh

# 4. 收集日志（可选）
TARGET_ROOT=/opt/cowagent-offline ./collect-logs.sh
```

`update.sh` 会依次执行：SHA256 校验 → 基线兼容性校验（packageVersion=1.1.0）→ 备份 → 安装文件 → 注册 MCP/Skill → 确认 COMPOSE_FILE 链 → `docker compose up -d`（带 browser 服务）→ Web 控制台就绪检查 → MCP 冒烟验收。任一步失败即中止，状态文件不会标记为 applied。

## 验收内容（update.sh 内置）

1. browser 容器运行且 healthcheck 通过；
2. 宿主机 `127.0.0.1:39222` CDP 可达；
3. toolpack 文件、mcp.json 注册（browser-dp 启用、browser-use 停用）、Skill 注册齐全；
4. 基线镜像容器内：Python 依赖导入、MCP stdio 握手、4 工具发现、health_check、data: URL 导航、snapshot、ref 点击、run_js、截图、page_info 全链路。

## 环境变量（compose/.env 可选调整）

| 变量 | 默认 | 说明 |
|---|---|---|
| `COW_BROWSER_MEM_LIMIT` | `4g` | 浏览器容器内存上限（含 swap） |
| `COW_BROWSER_CDP_PORT` | `39222` | 宿主机 loopback CDP 端口 |

## 常见问题

- **浏览器容器反复重启**：`docker logs <name>-browser` 查看崩溃原因；`storage/browser/profile` 权限需可写（脚本已 chmod）。
- **MCP 报连不上浏览器**：先 `docker ps` 看 browser 容器；再在宿主机 `curl http://127.0.0.1:39222/json/version`；最后在 CowAgent 容器内确认 `host.docker.internal` 解析（1.1.0 override 已内置）。
- **自签证书页面**：在 `mcp.json` 的 browser-dp env 加 `"DP_IGNORE_CERT_ERRORS": "1"` 后重启 cowagent 容器。
- **内存调整**：改 `.env` 的 `COW_BROWSER_MEM_LIMIT` 后执行 `docker compose -f docker-compose.yml -f docker-compose.override.yml -f docker-compose.browser.yml --env-file .env up -d`。
