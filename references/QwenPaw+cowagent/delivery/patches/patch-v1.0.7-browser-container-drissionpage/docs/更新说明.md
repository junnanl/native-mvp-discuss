# 更新说明：patch-v1.0.7-browser-container-drissionpage

## 这个补丁解决什么问题

内网环境（1.1.0 基线）下 browser-use 的浏览器频繁挂掉或重启。根因：

1. Chromium 由 browser-use MCP 进程代拉，MCP 退出时连带杀浏览器（EXIT trap），登录态随丢；
2. 浏览器与 CowAgent 同容器，内存压力大时相互拖垮，无独立资源配额与自愈；
3. `browser_exec(code)` 模式每次现生成代码，无固化、无沉淀，出错率高。

## 方案（三件事）

1. **浏览器独立容器**：新增 compose service `browser`，复用现有镜像 `cowagent-offline:2.1.7-base.1-dev`（内含 Chromium 120.0.6099.224），不传输任何新镜像。4G 内存上限（`COW_BROWSER_MEM_LIMIT` 可调）、`on-failure` 自愈、`/data/profile` 卷持久化登录态。CDP 通过 docker 容器网络直连（MCP 侧地址 `browser:9222`，由 apply.sh 注册为容器 links；宿主机 loopback `127.0.0.1:39222` 仅供运维验证）。
2. **DrissionPage 薄 MCP**：新增 `browser-dp` MCP（stdio，固定 4 工具：`browser_run`/`browser_snapshot`/`browser_screenshot`/`browser_exec`），引擎 DrissionPage **4.0.5.6**，通过 `existing_only` 接管浏览器容器 CDP——代码层面保证绝不在 CowAgent 容器内拉起浏览器。动作库含 50+ 固化动作（导航/标签页/读取/交互/等待/弹窗/JS/CDP/下载/上传/抓包/治理）。
3. **治理**：`health_check`、`cleanup_tabs`（tab 上限 8）、上传下载路径白名单、`browser_exec` 静态守卫（禁 os/subprocess/socket 等）。

## 版本与依赖

- Python 3.11.15：复用 1.1.0 基线 browser-use toolpack runtime，本补丁不新增解释器。
- mcp SDK 1.26.0：复制自基线 site-packages。
- DrissionPage 4.0.5.6 及全部 Python 依赖以 wheel 固化，现场**零安装**。
- 全部验证在 `--network none` / 无外网条件下进行；现场不执行 pip/uv/apt/npm。

## 前置条件

- 目标机已安装 `offline-install 1.1.0`（`manifest.json` packageVersion=1.1.0，镜像 2.1.7-base.1-dev）。
- 宿主机 Docker 支持 `mem_limit`/`shm_size`（任何近 5 年版本均可）。

## 上传/下载路径约定

- 浏览器容器内：`/data/uploads`、`/data/downloads`
- CowAgent 容器内（同一个宿主目录的两个视图）：`/home/agent/cow/browser-dp/uploads`、`/home/agent/cow/browser-dp/downloads`
- 动作层自动做两侧路径映射与白名单校验，越出白名单一律拒绝。
