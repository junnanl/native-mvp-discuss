# 常见问题

## 端口冲突

修改：

```text
compose/.env
```

将 `COW_WEB_PORT` 改成未占用端口后重新启动。

## 页面打不开

执行：

```bash
scripts/status.sh
scripts/verify.sh
scripts/collect-logs.sh
```

确认服务器防火墙是否放行 `COW_WEB_PORT`。

## 上传 PPT、Word、Excel 附件失败

如果日志出现：

```text
Permission denied: '/home/agent/cow/tmp/web_xxxxxxxx.pptx'
```

原因是宿主机挂载目录不可被容器内进程写入。执行：

```bash
scripts/start.sh
scripts/verify.sh
```

`start.sh` 会对运行和补丁挂载目录做宽松权限归一化，验证通过后重新上传。真实 `.env`、密钥、镜像 tar 和 SHA256 清单不属于宽松权限处理对象。

## 模型不可用

运行配置持久化后，优先检查：

```text
storage/cow/app-config/config.json
```

确认模型名、`bot_type`、Base URL 和 Key 正确。前台模型管理保存的值也会写入该文件。

如果日志出现：

```text
HTTPConnectionPool(host='127.0.0.1', port=xxxx): Connection refused
```

说明模型服务实际运行在宿主机，但 Base URL 错写成了容器内 `127.0.0.1`。修改规则：

- 模型在 CowAgent 宿主机：使用 `http://host.docker.internal:<端口>/v1`。
- 模型在其他内网服务器：使用实际内网 IP 或域名。
- Compose 必须包含 `host.docker.internal:host-gateway` 映射。

修改后重启并执行 `scripts/verify.sh`。不要把宿主机模型服务继续写成容器内 `127.0.0.1`。

真实 key 不会出现在交付包中，需要客户现场配置。

## 补丁应用后异常

先采集日志：

```bash
scripts/collect-logs.sh
```

再执行补丁包的 `rollback.sh` 回滚。
