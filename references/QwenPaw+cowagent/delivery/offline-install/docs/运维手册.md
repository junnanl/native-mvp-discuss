# CowAgent 运维手册

## 目录说明

```text
storage/
```

运行数据目录，需要备份。

```text
patch-mounted/
```

补丁输入目录，不放运行数据。

```text
source-mounted/
```

开发态源码覆盖目录，客户现场默认不用。

```text
toolpacks/
```

离线化 MCP、Skill 依赖和小型工具包目录。

## 端口调整

只修改宿主机端口：

```text
COW_WEB_PORT=18099
```

容器内端口保持 `9899`，不要修改。

## 多实例和命名冲突

如果同一台服务器部署多套 CowAgent，或已有同名 Compose 项目，需要同时修改：

```text
COW_COMPOSE_PROJECT_NAME=cowagent-offline-prod
COW_CONTAINER_NAME=cowagent-offline-prod
```

`COW_WEB_PORT`、`COW_COMPOSE_PROJECT_NAME` 和 `COW_CONTAINER_NAME` 应保持唯一，避免端口或 Compose 项目互相影响。

## 备份

建议备份：

```text
compose/.env
storage/
manifest.json
```

不需要备份：

```text
patch-mounted/
source-mounted/
toolpacks/
```

这些内容可由安装包或补丁包恢复。

## 升级

轻量补丁使用补丁包脚本。

如果补丁 manifest 中 `dependencyChange=true`，说明需要升级基础镜像，不能按轻量补丁处理。

## 上传失败排查

如果 Web 上传附件时报 `Permission denied: '/home/agent/cow/tmp/web_xxxxxxxx.xxx'`，说明宿主机挂载目录不可被容器内进程写入。

先执行：

```bash
scripts/start.sh
scripts/verify.sh
```

`start.sh` 会对 `storage/`、`patch-mounted/`、`source-mounted/`、`toolpacks/`、`model-assets/` 和 `scripts/` 做宽松权限归一化，保证所有宿主机用户和容器内用户都能读写运行目录。`verify.sh` 会检查上传目录是否可写。

真实 `.env`、密钥、镜像 tar、SHA256 清单和 manifest 不属于运行写入目录，不会作为宽松权限处理对象。
