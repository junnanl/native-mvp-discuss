# Evo-Harness 品牌启动止血包操作说明

## 适用范围

本止血包用于已经通过 `cowagent-offline-install-1.1.0.tar.gz` 部署、页面仍显示 CowAgent 品牌的内网环境。

根因是旧交付包遗漏了 `compose/docker-compose.override.yml`。前端和 `/version` 品牌补丁已经位于现场的 `patch-mounted/` 中，但容器启动时没有执行。

止血包只更新以下文件：

```text
/opt/cowagent-offline/compose/docker-compose.override.yml
```

它不会修改或删除：

- `compose/.env` 和模型密钥
- `storage/` 中的会话、工作区、配置和浏览器状态
- Docker 镜像
- `patch-mounted/` 和 `toolpacks/`

应用时会强制重建 CowAgent 容器，Web 页面会短暂中断。

本包只适用于旧 `1.1.0` 现场缺少 `compose/docker-compose.override.yml` 的情况。
如果现场已经存在该文件，脚本会在任何修改前停止并报错，避免覆盖现场自定义的环境变量、挂载或网络配置；这种情况应使用修正后的完整 `1.1.0` 交付包，或由管理员人工合并品牌配置。

## 应用

把止血包传入内网服务器后执行：

```bash
tar -xzf "cowagent-hotfix-v1.1.0-brand-bootstrap.1.tar.gz"
cd "hotfix-v1.1.0-brand-bootstrap.1"
TARGET_ROOT="/opt/cowagent-offline" bash "apply.sh"
```

如果现场目录归 `root` 所有，请使用：

```bash
sudo env TARGET_ROOT="/opt/cowagent-offline" bash "apply.sh"
```

成功标志：

```text
信息: 止血包验证通过：Compose、容器环境、前端和 /version 品牌均已生效
信息: 止血包应用成功，现场数据和 compose/.env 未被修改
```

随后在浏览器中强制刷新页面。Chrome、Edge 可使用 `Ctrl+F5`。

## 单独验证

```bash
cd "hotfix-v1.1.0-brand-bootstrap.1"
TARGET_ROOT="/opt/cowagent-offline" bash "verify.sh"
```

权限不足时给命令加 `sudo env`，例如：

```bash
sudo env TARGET_ROOT="/opt/cowagent-offline" bash "verify.sh"
```

也可以检查 Compose 合并结果：

```bash
cd "/opt/cowagent-offline/compose"
docker compose --env-file ".env" config \
  | grep -E "COW_BRAND_NAME|CHATGPT_ON_WECHAT_EXEC"
```

应看到 `COW_BRAND_NAME: Evo-Harness` 和包含 `bootstrap-brand.sh` 的启动命令。

## 回滚

```bash
cd "hotfix-v1.1.0-brand-bootstrap.1"
TARGET_ROOT="/opt/cowagent-offline" bash "rollback.sh"
```

回滚会删除止血包新增的 override（本包的适用现场原本没有 override）。如果应用前现场已有 override，止血包不会覆盖它，也不会产生需要回滚的变更。容器会再次重建，`storage/` 和 `compose/.env` 不受影响。

## 常见问题

### 提示目标目录不匹配

确认实际部署目录。如果不是 `/opt/cowagent-offline`，把 `TARGET_ROOT` 改为现场路径。

### 页面仍显示旧内容

先执行 `verify.sh`。验证通过后使用 `Ctrl+F5` 强制刷新，或使用无痕窗口访问。

### 现场使用 docker-compose

脚本会自动识别 `docker compose` 和 `docker-compose`，不需要修改命令。
