## 已经跑通的

### 定义驱动（方案 §2 铁律）

- `form_def.fields` 动态生成 Pydantic 校验模型，select 的 options 变成 Literal 约束；
  代码里没有任何具体字段名
- `flow_def.nodes` 驱动流程推进、角色校验、待办归属；节点上的 `form_id` 决定用哪张表单
- 角色是 `user` 表的数据，不是代码里的枚举（见方案 §15.1）
- 前端 `FormFields` 按定义渲染 label / 下拉 / 日期控件 / 必填标记

**判定方式**：`backend/tests/test_definition_driven.py` —— 只改数据库不改代码，
加字段、换选项、加新角色，行为跟着变。

### 硬标准：配一条完全不同的流程（方案 §12）

报销流程有自己的表单（事由/金额/发生日期/费用类别/发票号/备注）和自己的角色
（使用者提交 → 主管批 → 财务批 → 完成），与需求流程没有共用的代码分支。

**配这条流程只改了 `backend/app/definitions.json` 一个文件。**

**判定方式**：`backend/tests/test_hard_acceptance.py` —— 7 项，断言包括「报销表单里
没有需求单的字段」「评审角色不能批报销」这类反向断言，谁把字段或角色写回代码里就会红。

### AI 调用点（方案 §4 + §15.2 + §15.3）

五处，全部真调模型、全部 structured output、全部业务校验 + 失败回喂重试：

| 接口 | 干什么 | 业务校验拦什么 |
| --- | --- | --- |
| `/api/ai/dispatch` | 三选一路由 | route 不在三个值里、agent_id 不是已上线员工、flow_def_id 不存在 |
| `/api/ai/fill-form` | 按 form_def 填表 | 值不在 options 里、必填缺失、类型不对 |
| `/api/ai/resolve-view` | 挑视图出查询 | view 不在注册表、筛选条件该视图没有 |
| `/api/ai/skill-draft` | 生成 SKILL.md 草稿 | 太短、不是 markdown |
| `/api/ai/duplicate-check` | 重复建设检测 | agent_id 编造、weight 不在 0–1 |

`response_format` 不被支持时自动降级到纯提示词约束，并在响应的 `_model.schema_enforced`
里如实上报走了哪条路。**拿不到合格结果一律报 502，不降级成关键词匹配、不编造结果。**

### 组件与取数（方案 §3 / §6.6）

- 五类固定组件 metric / chart / table / graph / text，chart 与 graph 走 ECharts
- 视图注册表大部分从流程定义派生：新配一条流程自动多出列表/计数/节点分布三个视图，
  表格的列也来自 `form_def`
- `resolve-view` 只返回「看哪个视图、什么条件」，**不带数据**；取数、翻页、筛选由组件
  自己调 `/api/views/{key}`，不经过模型

### 数字员工对话（方案 §6.7）

- 三栏：过程 → 交流 → 结果
- 左栏执行进度**全部来自 CowAgent 的真实事件**（`phase` / `tool_start` / `tool_progress` /
  `tool_end`），工具名翻译成人话但状态照实；认不出的事件折叠显示，不丢弃
- 产物出右栏画布、累积、可单张删除，不塞进对话气泡
- 能力配置标注「此处为展示用，实际工具在 Evo-Harness 中配置」（方案 §2 记在案的技术债）

### 其它

- 登录 + 可见范围过滤（`visible_to` 查询时过滤，不做强制访问控制）
- 提示词建议来自 `prompt_suggestion` 表
- 员工上线必须挂在一条**已走完**的流程实例上，没有绕过流程的路径
- 指标卡名实相符：今日完成按 `finished_at` 当天算，本月新增按 `created_at` 当月算

## 开发运行

```bash
# 数据库（独立库，不要写进别的库）
export DATABASE_URL=postgresql://<user>:<pass>@<host>:5432/ai_native_oa

# 模型（OpenAI 兼容接口）
export MODEL_BASE_URL=http://<内网模型>/v1
export MODEL_NAME=<模型名>
export MODEL_API_KEY=<可留空>

# CowAgent
export COWAGENT_BASE_URL=http://<宿主IP>:<COW_WEB_PORT>
export COWAGENT_PASSWORD=<Web 访问密码，可留空>

backend/.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 18000
npm run dev --prefix frontend
```

默认页面 http://127.0.0.1:15173/ 。既有服务占用 8000，不使用该端口。

首次启动会建表并灌入 `backend/app/definitions.json` 的种子。种子是**按行补种**：
id 不存在就插入，已存在的一律不动——所以往种子文件里加一条流程，下次启动会进库，
而运行期在库里改过的定义不会被文件覆盖回去。**数据库是运行时的唯一事实源。**
